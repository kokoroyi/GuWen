# 架构说明

## 1. 总览

```text
┌──────────────────────────── browser ────────────────────────────┐
│  index.html / app.js        校字台、书库、导入                    │
│  punct_app.html / punct_app.js  句读台（iframe 挂载）             │
│  settings_ui.js              AI 设置弹窗（两个页面共用）           │
└───────────────────────────────┬──────────────────────────────────┘
                                │ localhost HTTP
┌───────────────────────────────▼──────────────────────────────────┐
│  app/server.py  FastAPI                                          │
│  ├─ pipeline.py        PaddleOCR PP-OCRv6（本地 OCR）             │
│  ├─ store.py           app/data 下的 JSON 书库/设置                │
│  ├─ punctgen.py        规则结构 / 句格 / 页范围                    │
│  ├─ structure_new.py   structure-new-v1 结构引擎                  │
│  ├─ llm_punct.py       句读提示词、保字重建、置信/纯度审计          │
│  └─ llm_client.py      OpenAI 兼容 HTTP 客户端                    │
└───────────────────────────────┬──────────────────────────────────┘
                                │ POST /chat/completions
                                ▼
                 任意 OpenAI 兼容 AI 接口（用户配置）
```

应用**没有**本地大模型运行时。`runtime/llm`、`runtime/models`、`llm_runtime.py` 均不在本仓库中。

## 2. 核心模块

### `app/server.py`

- 提供 FastAPI 服务和静态文件。
- 书库、OCR、校字、句读、导出、备份等 `/api/*` 接口。
- 整本 OCR 任务、整本句读任务的内存状态和后台线程。
- 服务默认监听 `127.0.0.1:8770`，可用 `GUWEN_PORT` 修改。

### `app/llm_client.py`

本仓库新增的 OpenAI 兼容客户端，替代原来的 llama.cpp 运行时启动逻辑。

- 从 `store.read_settings()` 读取 `llm_*` 配置。
- `normalize_base_url()` 接受根地址或粘贴的 `/chat/completions` 地址。
- `chat()` 发送标准 Chat Completions 请求：
  - `model`、`messages`、`stream: false` 为必带字段；
  - 可选 `max_tokens`、`temperature`、`reasoning_effort`、`stop`；
  - 额外参数 JSON 合并进请求体，但不能覆盖核心字段；
  - 429/5xx 自动重试两次；
  - 对 `max_tokens` / `max_completion_tokens`、温度不支持等常见 400 做有限兼容重试；
  - 不重试 401/403/404，也不静默忽略用户选择的 `reasoning_effort`。
- `list_models()` 调 `GET /models`。
- `test_connection()` 发一次最小 chat，返回模型、延迟和回复摘要。
- `public_config()` 不返回 API Key 明文。

### `app/llm_punct.py`

- 仍在本地完成提示词构造、分块、保字重建、`sanitize_output()`、`repair_chunk()`、结构审计和置信度计算。
- 只把“生成句读”这一步交给 `llm_client.chat()`。
- `punctuate_range()` 遇到接口/鉴权/网络错误会向上抛，整本任务状态会显示失败原因，而不是把每一块静默记为 fallback。

### `app/pipeline.py`

- PaddleOCR 检测 + 识别 + 切字。
- 模型名是 `PP-OCRv6_small_det` 和 `PP-OCRv6_medium_rec`；模型文件不提交，首次运行由 PaddleOCR 下载。
- 开发版启用了识别 oneDNN 和线程数自适应；检测 oneDNN 因 Paddle 3.3 PIR 限制保持关闭。

### 前端

- 原生 HTML/CSS/JS，无打包步骤。
- `app/static/index.html` 是书库和校字台。
- `app/static/punct_app.html` 是句读台，通过 iframe 挂载到主页面。
- `app/static/settings_ui.js` / `settings_ui.css` 是两个页面共用的 AI 设置弹窗。


`app/data/books/`、`jobs/`、`exports/`、`backup/`、`settings.json` 都在 `.gitignore` 中，不会进入仓库。

## 4. AI 配置接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/llm/status` | 当前配置的公开状态（不含密钥） |
| GET | `/api/llm/config` | 设置页读取配置（密钥只返回掩码提示） |
| PUT | `/api/llm/config` | 保存 Base URL / Key / 模型 / 思考强度 / 温度 / 超时 / 额外参数 |
| POST | `/api/llm/models` | 用当前表单地址和密钥拉取 `/models` |
| POST | `/api/llm/test` | 发一次最小 chat，验证连接 |
| GET/PUT | `/api/settings` | 非 AI 的全局设置；不会返回或修改 AI 密钥 |

## 5. 句读任务流程

```text
读取校字连续文本
  → structure-new-v1 生成结构
  → 找出纯念白/唱词块
  → 逐块调用 LLM：
       call_chat(block, max_tokens)
       → repair_chunk 对齐原文
       → sanitize_output 只保留合法中文标点
       → 保字校验失败则回退原块
  → 标点回填结构 / 纯度审计
  → 保存 punct.json（rev 乐观锁）
```

- 每次请求只包含一个结构块，不把整本一次性发给模型。
- 接口错误会中止并显示在任务状态；模型输出不合格只影响该块。
- 初版只执行一次；之后只能对选定结构执行局部 AI 标点。

## 6. 本地开发

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
python app/server.py
```

没有前端构建步骤；修改 `app/static/*` 后刷新页面即可。

## 7. 与旧分发版的差异

旧版 `D:\GuWenFin\GuWen-GPU` 是便携包，包含：

- `runtime/python` 便携 Python；
- `runtime/llm` / `runtime/llm_cpu` llama.cpp；
- `runtime/models/*.gguf` 本地 XunziALLM。
- `GuWen.exe` 托盘启动器。

本仓库只保留应用源码和必要的小型数据文件，删除了上述运行时、模型、EXE 和旧文档。AI 句读改走 OpenAI 兼容接口。
